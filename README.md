# 眾神殞落（垂直切片 v0.4）

回合制文字冒險 RPG 的可玩版本：一座會隨世界改變的地城（灰燼地窖，3 層＋兩階段 Boss）、4 名可選角色、完整戰鬥與戰報、雙人羈絆與黑盒子研究、記憶簿、模板短演出、營火談話。

純前端、零依賴、零建置也能跑；所有角色與數值皆為**測試用**，非正式設定。

## v0.4 新增

- **Boss 第二階段**：殘響騎士 HP 首次降到 50% 時進入第二階段（攻擊 +3、換成含「餘燼狂怒」的技能組）。寫成 `phase_changed` 事件，有來源傷害事件、可重播、驗證器會擋下偽造的階段事件。
- **地城隨世界改變（P06）**：第一次擊敗 Boss 後，灰燼地窖進入「餘燼回流」：新敵人餘燼犬、敵人強化（HP 130%／攻擊 120%）、新掉落（燼犬牙刃、回燼胸甲）、專屬奇遇「倒流的灰燼」。Boss 首殺獎勵只給一次。
- **營火談話（P05／P08 受限意圖）**：每人每天一次，只能選「聊聊最近的戰鬥／問起過去／道謝」。台詞只引用記憶簿與戰報的真實數字；好感（0–10）只解鎖作者寫好的過去，不影響任何戰鬥數值。
- 設定頁「回報問題」顯示版本、種子、天數，方便回報。
- v0.3 存檔可直接讀取（自動補上新欄位）。

## 本地遊玩

```bash
npm run serve          # 或任何靜態伺服器
# 打開 http://localhost:8080
```

或先 `npm run build`，直接雙擊 `dist/index.html`（單一檔案，可離線）。

## 測試

```bash
npm test               # 單元測試 19 項（重播、快照重算、統計、安全白名單、黑盒子、記憶、演出、存檔、Boss 階段、世界改變、營火談話）
npm run balance        # 批次平衡模擬（每個種子連續 5 次遠征）
npm install && npx playwright install chromium
npm run e2e            # 瀏覽器端對端 33 項：桌機＋手機
npm run build && npm run e2e:dist   # 測打包後的單檔
```

## 上架到 GitHub Pages

1. 在 GitHub 建立 repo，推上 `main`。
2. Settings → Pages → Source 選 **GitHub Actions**。
3. 之後每次推到 `main`，`.github/workflows/ci-pages.yml` 會先跑全部測試，通過才部署 `dist/`。

## 結構

```text
src/rng.js        決定性亂數（可存檔）
src/data.js       角色、技能、敵人、地城（含世界狀態）、奇遇、羈絆、裝備
src/engine.js     戰鬥引擎（唯一權威；append-only 事件、指令白名單、Boss 階段、重播、一致性驗證）
src/report.js     戰報：結算／簡易／詳細／統計／HP 曲線（純函式）
src/memory.js     結構化記憶（只寫規則判定的重大事實）
src/narration.js  模板短演出（只引用真實事件；宿敵與階段轉換用作者文本）
src/talk.js       營火談話（受限意圖選單；只引用真實記憶與統計）
src/game.js       遊戲狀態：營地、遠征、世界狀態、戰後結算、訓練場、存讀檔
src/ui.js         介面
scripts/build.mjs 打包成單一 HTML
```

## 設計原則（摘自專案文件）

- 引擎是唯一權威；戰報、演出、記憶、談話都只讀事件紀錄。
- 一致性驗證不通過就不寫存檔。
- 雙人羈絆只算兩人；換第三人不影響老搭檔；旁觀演出不產生數值。
- 黑盒子：隱藏效果的實際數值一定出現在戰報裡，只是顯示「未解析效果」，要靠訓練場對照實驗確認。
- 玩家指令只接受 `{skill_id, target_id}`；營火談話只接受 `{actor_id, intent}`；其他一律拒絕。

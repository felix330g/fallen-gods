# 戰報系統規格（RPG 戰報系統製作 V1.0）

> 來源：Claude 專案「ai 文字遊戲」的戰報 skill。目前實作為 JavaScript（純前端），不是原文預設的 Python。

## 必須遵守的已確認設計
1. 戰鬥採回合制、由**程式規則**判定行動順序、命中、技能、傷害、狀態、勝敗；AI 不決定數值與結果。
2. **四種視圖共享同一份戰鬥事實**：一般結算、詳細逐回合戰報、統計／狀態、角色短演出。戰報可跳轉回合、篩選角色、技能、傷害、狀態。
3. 詳細戰報必須可查看每個回合的每個行動及前後狀態；技能發動／未發動、命中、暴擊、抵抗、冷卻與減傷來源需能解釋。統計包含輸出、承傷、治療、技能次數及 HP 曲線。
4. 角色演出是**短句**：一兩句對話、動作、心聲或旁觀視角，不要把每一回合變成小說。普通刷怪應可快速略過；重大事件才增加演出。
5. 特殊演出由**預定義的可檢測條件**觸發，例如首次擊殺、擊敗仇敵、保護瀕死隊友、初次成功連攜、首次發動新技能。AI 不能創造不存在的事件。
6. **只計算雙人羈絆**；固定專屬羈絆與任意兩人的通用合作熟練度並存。新人加入不能削弱原本兩人的默契。不設整隊默契數值。第三人可以旁觀演出，但旁觀本身不直接創造戰鬥加成。
7. 配將、技能搭配、隱藏連動有研究價值。黑盒子可隱藏「條件」或部分「規則」，但必須可重複驗證；系統精確保存真正判定。玩家可從戰報取得線索，進一步測試並解鎖知識。不能讓 AI 隨機發明隱藏加成。
8. 世界觀、大型劇情與重要人物命運有確定規則；戰報只能引用已存在的角色、關係、記憶、仇敵 ID 與戰鬥結果。
9. 重要事件寫入**結構化角色記憶**，普通戲劇性措辭不自動成為世界事實；台詞中的新承諾、過去、親屬關係、技能效果都不得偷偷永久化。
10. 使用者明確擔憂自由輸入帶來 prompt injection 與越權。所有 AI 輸出視為不可信文字，只能透過白名單欄位與驗證器呈現；任何狀態修改都由可信程式執行。

## 開發協作模式
- 先檢查現有程式與資料。
- 每次交付列出：本次目標、輸入、輸出、確定規則、未定平衡參數、測試結果、下一步。
- 說明何者為【已確定】、【建議預設】、【待討論】；不要把示範數字與角色示例當正式設定。
- 嚴格遵循「先引擎／事件真相，後顯示／AI 美化」的順序。

## 實作流程要點
1. **不可變的事件契約**：依 [event-schema.md](event-schema.md)。全部事件具 `battle_id`、`turn`、`sequence`、`actor_id`、`event_type`、原始數值、結果與引用 ID。區分「嘗試、判定、套用、狀態變化」。
2. **確定性回合引擎**：玩家選擇或預設策略 → 速度排序與同速規則 → 行動合法性 → 技能冷卻／成本 → 命中／效果判定 → 傷害與治療 → 狀態增減與回合結算 → 結束條件。所有隨機數採明確 seed；同一輸入、規則版本、seed，結果完全一致。事件只追加不回頭改寫。
3. **一般結算＋詳細戰報**：點擊任何統計、狀態或關鍵片段，可定位到來源事件；提供角色／技能／事件類型篩選。
4. **統計與狀態**：從實際已套用事件產生；確保總和與逐行事件相符。
5. **短演出事件選擇器**：條件產生候選 → 排序、去重、冷卻與篇幅限制。重要劇情的關鍵句使用作者文本。見 [narration-and-memory.md](narration-and-memory.md)。
6. **AI 文字生成器（可選，必須有離線模板 fallback）**：只接收最小必要事實包；輸出限定 `lines`、`tone`、`references_event_ids` 等欄位；schema 校驗、引用驗證、禁造事實檢查後才顯示；失敗改用固定模板。範例見 [examples/narration-contract.json](examples/narration-contract.json)。
7. **雙人羈絆與黑盒子**：pair 鍵排序；效果在引擎 modifier stack 中算出並具來源 ID；玩家所見的實際結算數值不能說謊，未知修正顯示「未解析效果」。見 [pair-synergy-and-black-box.md](pair-synergy-and-black-box.md)。
8. **記憶、回放與測試**：重要事件以去重鍵寫入客觀記憶；戰報可完整離線回放。驗收依 [roadmap-and-acceptance.md](roadmap-and-acceptance.md)。

## 自我檢查
- 是否所有角色行動、數值、勝敗與狀態，都能回指 event ID？
- 詳細戰報是否顯示不觸發／閃避／抵抗與持續效果？
- 前後 HP、護盾、治療、狀態時序是否一致？
- 是否確保演出符合角色視角與知識，第三人觀察不等於讀心？
- 是否沒有強行把短演出變成正式劇情？
- 是否沒有整隊默契數值或新人入隊懲罰？
- 是否能離線觀看戰報且與 AI 文字無關？
- 是否區分事實揭露與黑盒子的規則揭露，避免誤導玩家？
